# 改进规则

> 供「打榜 RoboTwin」研读任务参考：队员在提出基模改进思路时，须落在下列合规框架内。

## 0. 任务与目标

- 基于**统一官方基座 VLA 权重（v2）**&#x5B8C;成训练与调优，提升模型在 RoboTwin 仿真基准上的任务成功率。
- 训练起点必须来自该基座；无强制保留的模块清单、无参数比例要求。
- 可用 LoRA 微调，但需合并回基座、提交全量权重。

## 1. 数据

- **唯一允许的训练监督来源**：benchmark release 的 **clean 演示数据**（50 任务 × 50 条）。
- **randomized 数据仅可用于测试**，任何比例、任何形式均禁止参与训练。
- **禁止外部数据**（真机自采、第三方机器人数据集等）。
- 训练监督必须严格来自 demonstration 本身，保持在 **BC（模仿学习）** 框架内。

## 2. 允许的技术范畴

1. **数据处理**
   - 训练期像素级**视觉增广（白名单）**：亮度/对比度/饱和度/色温抖动、高斯噪声、椒盐噪声、高斯/轻微运动模糊、小范围随机裁剪/平移/缩放、随机遮挡（Cutout/Random Erasing）、JPEG 压缩伪影。
   - 轨迹**质量过滤**（jerk / Z-score 低质量剔除）、**seen 池内指令替换**、按数据自身统计量**重加权**。
2. **模型结构**：允许大幅度结构改造；允许引入**公开、冻结**的 vision / depth / segmentation 编码器（须在 README 注明来源）；允许 LoRA 合并回基座。
3. **训练策略**：优化器 / 学习率、归一化统计、动作表示、损失函数、EMA（最终权重平均）、基座自蒸馏（以参赛方自训权重为教师）均允许。
4. **推理策略（单一权重内）**：动作 chunk 长度调整与 replanning、action smoothing、推理精度（bf16/fp32）、计算图编译开关。
   - 时间维输出平均（temporal ensemble）与基于模型自身输出统计的置信度门控
5. **冻结公开感知教师（辅助监督例外）**：可使用公开发布且全程冻结的通用感知模型（如深度估计、视频编码器）输出作辅助训练目标，须同时满足：  
   来源公开、通用感知（未在任务数据上微调）、全程冻结、输入仅含 release 资产、仅作辅助目标（不得用于筛选/加权/生成伪标签）、主监督仍来自 clean 演示、如实披露名称/来源/版本/接入位置/辅助损失权重。

## 3. 禁止的技术手段

- **数据**：外部数据；randomized 进训练；自建 randomization（抠图换背景、插/删/换物体、改场景几何/桌面高度、改光照/重渲染阴影、用生成模型编辑图像）；simulator 额外 rollout 训练；unseen 指令以任何形式进训练；LLM 生成新指令；HER 伪目标重标注（新增 release 中不存在的配对）。
- **模型起点**：以官方后训练权重作为训练起点或教师（复现官方双教师蒸馏配方除外）。
- **推理形态**：task-specific 路由（按任务 ID 的 LoRA/adapter/head/checkpoint）；多 checkpoint / 多 model ensemble；多 seed 投票、test-time adaptation；推理加载第二份权重；失败检测触发重置 episode 重执行。
- **学习方法**：超出 BC 框架——在线 RL、DAgger、以环境打分做筛选/加权、世界模型 RL、价值/优势加权自举等（凡监督不可写为 release 数据纯函数者均禁）。

## 4. 硬性规则红线

- **单一权重**：推理阶段仅加载一份由训练产出的权重；不允许按任务路由、多模型集成。
- **clean 演示唯一监督**：任何监督信号须可写为 release 数据的纯函数。
- **如实披露**：引入的公开模块、LoRA 形态、评测环境细节须在 Config / README 说明，保证可复现。

## 5. 对「改进思路」的提示

- 改进应优先在**合规白名单**内寻找：数据增广与过滤、训练策略（损失/动作表示/EMA）、推理策略（replanning/smoothing）、以及冻结公开感知教师的辅助监督。
- 任何触碰「禁止轴」的设计（自建 randomization、多权重路由、非 BC 自监督）一律不合规，勿提交。
- 完整实验进展与既有方案见团队仓库（见任务说明中的 GitHub 链接），**新思路不得与仓库已有实验重复**。
